# SECTION 3 — LOAD AND MERGE CLIMATE DATA
#
# NASA POWER delivers one CSV per variable. Each file has:
#   • 9 header lines of metadata
#   • Then: PARAMETER, YEAR, LAT, LON, JAN, FEB, ..., DEC, ANN
#
# We reshape each file from wide (12 monthly columns) to long (one row per
# grid-point × year × month), then merge all 5 into a single DataFrame.
# =============================================================================

print("=" * 65)
print("  SECTION 3 — LOADING AND MERGING DATA")
print("=" * 65)

monthly_dfs = []   # One DataFrame per climate variable, in long format

for var_name, (col_code, filename) in DATA_FILES.items():

    path = os.path.join(DATA_DIR, filename)

    # Read the CSV, skipping the 9-line NASA metadata header
    raw = pd.read_csv(path, skiprows=NASA_SKIPROWS)

    # Melt: convert the 12 monthly columns (JAN … DEC) into rows
    #   Before melt:  YEAR=2005, LAT=6, LON=3.125, JAN=120, FEB=95, ...
    #   After  melt:  YEAR=2005, LAT=6, LON=3.125, MONTH='JAN', RH2M=120
    #                 YEAR=2005, LAT=6, LON=3.125, MONTH='FEB', RH2M=95  ...
    long = raw.melt(
        id_vars    = ['PARAMETER', 'YEAR', 'LAT', 'LON'],
        value_vars = MONTH_ABBR,
        var_name   = 'MONTH',
        value_name = col_code
    ).drop(columns=['PARAMETER'])   # PARAMETER column just repeats the name

    monthly_dfs.append(long)
    print(f"  Loaded {var_name:>12s}  ({col_code:>17s}) — {len(long):,} rows")

# Merge all 5 DataFrames on the 4 shared identifier columns
# reduce() applies pd.merge() repeatedly:  df1 JOIN df2 JOIN df3 JOIN …
merged = reduce(
    lambda L, R: pd.merge(L, R, on=['YEAR', 'LAT', 'LON', 'MONTH']),
    monthly_dfs
)

# Add integer month column (JAN→1, DEC→12) for sorting and modelling
merged['MONTH_NUM'] = merged['MONTH'].map(MONTH_TO_NUM)

# Sort chronologically within each spatial grid point
merged = merged.sort_values(['LAT','LON','YEAR','MONTH_NUM']).reset_index(drop=True)

# =============================================================================
# SECTION 5 — FEATURE ENGINEERING
#
# Flooding is rarely caused by a single month's rain. It results from
# compound events: soil already saturated from previous months, ongoing
# heavy rain on top of that, and a moisture-laden atmosphere.
#
# We therefore engineer five new time-lagged features:
#   RAIN_3M  — how much rain fell over the last 3 months
#   RAIN_6M  — how much rain fell over the last 6 months
#   RAIN_LAG1— rainfall in the previous month
#   RAIN_LAG2— rainfall two months ago
#   RH_LAG1 — humidity in the previous month (soil moisture proxy)
#
# All rolling/lag computations are done PER SPATIAL GRID POINT using
# groupby + transform(), which keeps the DataFrame index intact so that
# the LAT and LON columns are not lost.
# =============================================================================

print("=" * 65)
print("  SECTION 5 — FEATURE ENGINEERING")
print("=" * 65)

# Group by spatial location so rolling and shift operate within each (LAT,LON) series
grp = merged.groupby(['LAT','LON'])

# 3-month cumulative rainfall:
#   Example — if Jul=200, Jun=150, May=100 → RAIN_3M for Jul = 450 mm
#   min_periods=1 keeps the first month of each series (no NaN for period start)
merged['RAIN_3M']   = grp['PRECTOTCORR_SUM'].transform(
    lambda x: x.rolling(3, min_periods=1).sum()
)

# 6-month cumulative rainfall (half-year moisture memory)
merged['RAIN_6M']   = grp['PRECTOTCORR_SUM'].transform(
    lambda x: x.rolling(6, min_periods=1).sum()
)

# Last month's rainfall: shift(1) moves values one row forward within each group
# Row for February gets January's value; January gets NaN (no prior month)
merged['RAIN_LAG1'] = grp['PRECTOTCORR_SUM'].transform(lambda x: x.shift(1))

# Rainfall two months ago
merged['RAIN_LAG2'] = grp['PRECTOTCORR_SUM'].transform(lambda x: x.shift(2))

# Last month's relative humidity (atmospheric moisture memory)
merged['RH_LAG1']   = grp['RH2M'].transform(lambda x: x.shift(1))

# Drop rows where any lagged feature is NaN.
# This affects only the very first 1–2 months of each spatial series,
# which have no prior month to reference.
merged = merged.dropna().reset_index(drop=True)

print(f"  New features: RAIN_3M, RAIN_6M, RAIN_LAG1, RAIN_LAG2, RH_LAG1")
print(f"  Dataset after dropping NaN rows: {len(merged):,} rows\n")


# =============================================================================
# SECTION 6 — CREATE FLOOD RISK LABELS  (proxy method)
#
# We lack a verified Nigeria flood event database, so we create PROXY LABELS
# using a multi-condition threshold approach consistent with the flood hydrology
# literature (see Tabbussum & Dar 2021; Guan et al. 2023).
#
# Label = HIGH RISK (1) when at least MIN_CONDS of these 3 conditions hold:
#   1. Monthly rainfall    ≥ 80th percentile of all values
#   2. Relative humidity   ≥ 70th percentile of all values
#   3. 3-month accumulation≥ 70th percentile of all values
#
# ⚠ IMPORTANT LIMITATION:
#   Because the model predicts the same thresholds used to create the labels,
#   accuracy is artificially inflated. ROC-AUC and F1-Score are more reliable
#   performance indicators. This limitation is explicitly stated in Section 21.
# =============================================================================

print("=" * 65)
print("  SECTION 6 — FLOOD RISK LABELS")
print("=" * 65)

# Compute thresholds from the entire 2000–2025 dataset
thresh_rain = merged['PRECTOTCORR_SUM'].quantile(RAIN_PCTILE)
thresh_rh   = merged['RH2M'].quantile(RH_PCTILE)
thresh_r3m  = merged['RAIN_3M'].quantile(R3M_PCTILE)

print(f"  Rainfall  threshold ({int(RAIN_PCTILE*100)}th pctile): {thresh_rain:.2f} mm/day")
print(f"  Humidity  threshold ({int(RH_PCTILE*100)}th pctile): {thresh_rh:.2f} %")
print(f"  3-M accum threshold ({int(R3M_PCTILE*100)}th pctile): {thresh_r3m:.2f} mm")

# Risk score: 0, 1, 2, or 3 depending on how many conditions are met
merged['RISK_SCORE'] = (
    (merged['PRECTOTCORR_SUM'] >= thresh_rain).astype(int) +  # condition 1
    (merged['RH2M']            >= thresh_rh).astype(int)   +  # condition 2
    (merged['RAIN_3M']         >= thresh_r3m).astype(int)     # condition 3
)

# Binary flood risk label
merged[TARGET] = (merged['RISK_SCORE'] >= MIN_CONDS).astype(int)

n1 = merged[TARGET].sum()
n0 = len(merged) - n1
print(f"\n  Label distribution:")
print(f"    Low Risk  (0): {n0:,}  ({n0/len(merged):.1%})")
print(f"    High Risk (1): {n1:,}  ({n1/len(merged):.1%})")
print(f"\n  ⚠  Class imbalance: a naive 'always-predict-zero' baseline")
print(f"     scores {n0/len(merged):.1%} accuracy — so high accuracy is expected.\n")


# =============================================================================
# SECTION 7 — PREPARE DATA  (split, scale, reshape)
#
# We split CHRONOLOGICALLY (not randomly) to respect the time-series nature
# of the data. Training on future data and testing on past would be leakage.
#
# StandardScaler is fitted ONLY on training data, then applied to test.
# If we fit on all data, test-set statistics leak into the normalisation.
# =============================================================================

print("=" * 65)
print("  SECTION 7 — DATA PREPARATION")
print("=" * 65)

# Boolean masks to separate training and test rows
train_mask = merged['YEAR'] <= TRAIN_END
test_mask  = merged['YEAR'] >= TEST_START

# Feature matrices and target vectors
X_train_raw = merged.loc[train_mask, FEATURES].values
y_train     = merged.loc[train_mask, TARGET].values
X_test_raw  = merged.loc[test_mask,  FEATURES].values
y_test      = merged.loc[test_mask,  TARGET].values

# Keep the full test DataFrame (including LAT, LON) for spatial mapping
df_test = merged[test_mask].copy().reset_index(drop=True)

print(f"  Training rows : {len(y_train):,}  (years {2000}–{TRAIN_END})")
print(f"  Test rows     : {len(y_test):,}   (years {TEST_START}–2025)")
print(f"  Features      : {len(FEATURES)}")

# Fit scaler on training data only, then transform both sets
scaler  = StandardScaler()
X_train = scaler.fit_transform(X_train_raw)
X_test  = scaler.transform(X_test_raw)

# For LSTM: reshape to (samples, 1 timestep, features)
# LSTM expects 3-D input; we use 1 timestep because lag features
# are already embedded as separate columns.
X_train_lstm = X_train.reshape(X_train.shape[0], 1, len(FEATURES))
X_test_lstm  = X_test.reshape(X_test.shape[0],  1, len(FEATURES))

print(f"\n  Scaler fitted on training data only.")
print(f"  ANN  input shape : {X_train.shape}")
print(f"  LSTM input shape : {X_train_lstm.shape}\n")

# Shared training callbacks used by both ANN and LSTM
CALLBACKS = [
    EarlyStopping(
        monitor='val_loss',
        patience=10,                 # Wait 10 epochs before stopping
        restore_best_weights=True,   # Roll back to the lowest val_loss checkpoint
        verbose=0
    ),
    ReduceLROnPlateau(
        monitor='val_loss',
        factor=0.5,    # Multiply learning rate by 0.5 when stalling
        patience=5,    # Wait 5 epochs before reducing
        verbose=0
    ),
]


# =============================================================================
# SECTION 8 — BUILD AND TRAIN THE ANN
#
# An ANN (Artificial Neural Network) is a feed-forward network.
# Information flows in one direction: Input → Hidden Layers → Output.
#
# Architecture  : 11 → Dense(128) → BN → DO(0.3)
#                      → Dense(64)  → BN → DO(0.3)
#                      → Dense(32)  → DO(0.2)
#                      → Dense(1, sigmoid)
#
# Key design choices:
#   • ReLU activation: f(x) = max(0, x) — avoids vanishing gradients.
#   • BatchNormalisation: normalises activations — speeds up training.
#   • Dropout: randomly zeroes neurons — prevents overfitting.
#   • Sigmoid output: squashes prediction to (0,1) = flood probability.
# =============================================================================

print("=" * 65)
print("  SECTION 8 — ANN MODEL")
print("=" * 65)

ann = Sequential([

    # --- Input → Hidden Layer 1 (128 neurons) --------------------------------
    Dense(128, activation='relu', input_shape=(len(FEATURES),)),
    # 128 neurons allows the network to learn complex, non-linear combinations
    # of the 11 climate features. More neurons = more expressive capacity.

    BatchNormalization(),
    # Normalises the 128 activations within each mini-batch to mean≈0, std≈1.
    # This prevents "covariate shift" and allows higher learning rates.

    Dropout(0.3),
    # During training, randomly set 30% of the 128 outputs to zero.
    # Each training step uses a different random subset of neurons,
    # so the network cannot rely on any one neuron being present.
    # At inference (prediction), all neurons are active but scaled by 0.7.

    # --- Hidden Layer 2 (64 neurons) -----------------------------------------
    Dense(64, activation='relu'),
    BatchNormalization(),
    Dropout(0.3),

    # --- Hidden Layer 3 (32 neurons) -----------------------------------------
    Dense(32, activation='relu'),
    Dropout(0.2),  # Lighter dropout near the output layer

    # --- Output layer: single neuron with sigmoid ----------------------------
    Dense(1, activation='sigmoid'),
    # Sigmoid: σ(x) = 1 / (1 + e^{-x})
    # Maps any real number to (0, 1).
    # Output is interpreted as P(FLOOD_RISK = 1 | features).
    # Decision: if P ≥ 0.5 → predict High Risk; else → predict Low Risk.
])

ann.compile(
    optimizer = Adam(learning_rate=LEARNING_RATE),
    loss      = 'binary_crossentropy',
    # For a predicted probability p and true label y ∈ {0,1}:
    #   L = −[y·log(p) + (1−y)·log(1−p)]
    # Penalises confident wrong predictions more than uncertain ones.
    metrics   = ['accuracy'],
)

print("\n  ANN Architecture:")
ann.summary()

print("\n  Training ANN ...")
ann_start   = time.time()
ann_history = ann.fit(
    X_train, y_train,
    validation_split = VAL_FRACTION,
    epochs           = MAX_EPOCHS,
    batch_size       = BATCH_SIZE,
    callbacks        = CALLBACKS,
    verbose          = 0,
)
ann_time   = time.time() - ann_start
ann_epochs = len(ann_history.history['loss'])

# Generate probabilities and binary predictions on the test set
ann_prob = ann.predict(X_test, verbose=0).flatten()
ann_pred = (ann_prob >= 0.5).astype(int)

print(f"  ANN done — {ann_epochs} epochs in {ann_time:.1f}s\n")


# =============================================================================
# SECTION 9 — BUILD AND TRAIN THE LSTM
#
# LSTM (Long Short-Term Memory) is a recurrent neural network designed to
# capture long-range dependencies in sequential data.
#
# Inside each LSTM cell, three learnable gates control information flow:
#   Forget gate : f_t = σ(W_f·[h_{t-1}, x_t] + b_f)
#     → What fraction of the previous memory to retain
#   Input  gate : i_t = σ(W_i·[h_{t-1}, x_t] + b_i)
#     → What new information from the current step to add to memory
#   Output gate : o_t = σ(W_o·[h_{t-1}, x_t] + b_o)
#     → What part of the current memory to output as the hidden state
#
# Architecture  : LSTM(128, return_seq=True) → DO(0.3)
#                 → LSTM(64) → DO(0.3) → Dense(32) → Dense(1, sigmoid)
#
# Why LSTM underperforms ANN here:
#   Our features are MONTHLY-AGGREGATED with explicit lag columns already
#   embedded. LSTM's sequential memory advantage is most powerful on
#   daily or hourly data where patterns unfold over many timesteps.
#   With 1 timestep and pre-computed lags, the advantage largely disappears.
# =============================================================================

print("=" * 65)
print("  SECTION 9 — LSTM MODEL")
print("=" * 65)

lstm = Sequential([

    # --- First LSTM layer (128 cells) ----------------------------------------
    LSTM(
        128,
        return_sequences=True,             # Pass output at EVERY timestep forward
        input_shape=(1, len(FEATURES))     # (1 timestep, 11 features)
    ),
    # 128 memory cells, each maintaining:
    #   cell_state   c_t — long-term information
    #   hidden_state h_t — short-term output passed to the next layer
    # return_sequences=True keeps the time dimension for the next LSTM layer.

    Dropout(0.3),

    # --- Second LSTM layer (64 cells) ----------------------------------------
    LSTM(64, return_sequences=False),
    # return_sequences=False: only the final timestep's h_t is passed forward.
    # This condenses the sequence into a fixed-length feature vector.

    Dropout(0.3),

    # --- Dense output head ---------------------------------------------------
    Dense(32, activation='relu'),
    Dense(1,  activation='sigmoid'),
])

lstm.compile(
    optimizer = Adam(learning_rate=LEARNING_RATE),
    loss      = 'binary_crossentropy',
    metrics   = ['accuracy'],
)

print("\n  LSTM Architecture:")
lstm.summary()

print("\n  Training LSTM ...")
lstm_start   = time.time()
lstm_history = lstm.fit(
    X_train_lstm, y_train,
    validation_split = VAL_FRACTION,
    epochs           = MAX_EPOCHS,
    batch_size       = BATCH_SIZE,
    callbacks        = CALLBACKS,
    verbose          = 0,
)
lstm_time   = time.time() - lstm_start
lstm_epochs = len(lstm_history.history['loss'])

lstm_prob = lstm.predict(X_test_lstm, verbose=0).flatten()
lstm_pred = (lstm_prob >= 0.5).astype(int)

print(f"  LSTM done — {lstm_epochs} epochs in {lstm_time:.1f}s\n")

def evaluate(name, y_true, y_pred, y_prob, train_secs, n_epochs):
    """
    Compute and display all classification metrics for one model.

    Parameters
    ----------
    name        : str   — 'ANN' or 'LSTM'
    y_true      : array — True binary labels
    y_pred      : array — Predicted binary labels (threshold 0.5)
    y_prob      : array — Predicted probabilities (0..1)
    train_secs  : float — Wall-clock training time in seconds
    n_epochs    : int   — Number of epochs the model ran

    Returns
    -------
    dict — All metric values for saving and plotting
    """
    acc  = accuracy_score(y_true, y_pred)
    prec = precision_score(y_true, y_pred, zero_division=0)
    rec  = recall_score(y_true, y_pred, zero_division=0)
    f1   = f1_score(y_true, y_pred, zero_division=0)
    auc  = roc_auc_score(y_true, y_prob)
    cm   = confusion_matrix(y_true, y_pred)

    print(f"\n  {'─'*50}")
    print(f"  {name}")
    print(f"  {'─'*50}")
    print(f"  Accuracy   : {acc:.4f}  — (TP+TN)/total")
    print(f"  Precision  : {prec:.4f}  — TP/(TP+FP)  → alert reliability")
    print(f"  Recall     : {rec:.4f}  — TP/(TP+FN)  → flood detection rate")
    print(f"  F1-Score   : {f1:.4f}  — harmonic mean of P & R")
    print(f"  ROC-AUC    : {auc:.4f}  — 1.0=perfect, 0.5=random")
    print(f"  Train time : {train_secs:.1f}s  |  Epochs: {n_epochs}")
    print()
    print(classification_report(y_true, y_pred,
                                target_names=['Low Risk','High Risk'], digits=4))
    return dict(name=name, acc=acc, prec=prec, rec=rec,
                f1=f1, auc=auc, cm=cm, time=train_secs, epochs=n_epochs)

def interpolate(col):
    """
    Interpolate a spatial risk column from 336 sparse points
    onto the 500×500 regular grid using cubic spline interpolation.
    Returns a 2-D array clipped to [0, 1], with NaN filled by 0.
    """
    z = griddata(SRC_PTS, spatial[col].values,
                  (LON_MESH, LAT_MESH), method='cubic')
    return np.clip(np.nan_to_num(z, nan=0.0), 0.0, 1.0)

# =============================================================================
# SECTION 14 — FIGURE 4  :  FEATURE IMPORTANCE
#
# Permutation importance measures how much the F1-Score drops when a single
# feature is randomly shuffled (its values become random noise).
#   Large drop → feature is critical; model relies on it.
#   Near-zero  → model doesn't use that feature much.
#
# We use F1-Score (not accuracy) as the scoring metric because our classes
# are imbalanced — F1 is more sensitive to changes in flood detection quality.
#
# The radar chart (right) shows the top-6 features' relative importance
# normalised to [0,1] for easy visual comparison.
# =============================================================================

print("  SECTION 14 — FIGURE 4: FEATURE IMPORTANCE")

class KerasWrapper(BaseEstimator, ClassifierMixin):
    """
    Minimal scikit-learn compatible wrapper around a Keras model.
    Required because permutation_importance() expects sklearn-style objects.
    """
    def __init__(self, model):
        self.model = model
    def fit(self, X, y):
        return self   # Already trained; nothing to do
    def predict(self, X):
        return (self.model.predict(X, verbose=0).flatten() >= 0.5).astype(int)
    def score(self, X, y):
        return f1_score(y, self.predict(X))  # Use F1 as our scoring metric

print("  Computing permutation importance (5 repeats) ...")
perm = permutation_importance(
    KerasWrapper(ann), X_test, y_test,
    n_repeats=5,              # Repeat shuffling 5 times; average for stability
    random_state=RANDOM_SEED,
    scoring='f1'
)

fi = pd.DataFrame({
    'feature':    FEATURES,
    'importance': perm.importances_mean,
    'std':        perm.importances_std,
    'label':      [FEAT_LABELS[f] for f in FEATURES],
}).sort_values('importance', ascending=False).reset_index(drop=True)

print("  Top 5 features:")
for _, row in fi.head(5).iterrows():

# SECTION 21 — VALIDITY DISCUSSION
#
# Why the 99%+ accuracy is methodologically inflated — four root causes.
# This section is printed to console AND should be included in the paper's
# Limitations section (typically Section 4 or 5).
# =============================================================================

print("\n" + "=" * 65)
print("  SECTION 21 — VALIDITY DISCUSSION")
print("=" * 65)

ann_acc_pct  = ann_m['acc'] * 100
lstm_acc_pct = lstm_m['acc'] * 100
baseline_pct = (1 - y_test.mean()) * 100

print(f"""
  ╔═══════════════════════════════════════════════════════════════╗
  ║     WHY {ann_acc_pct:.2f}% ACCURACY IS LIKELY INFLATED (ANN)        ║
  ╚═══════════════════════════════════════════════════════════════╝

  Root Cause 1 — PROXY LABELS  (most significant)
  ─────────────────────────────────────────────────
  The FLOOD_RISK labels were constructed from thresholds on the
  SAME variables the model uses as inputs (rainfall, humidity,
  3-month accumulation). The model is not detecting real floods —
  it is recovering the deterministic rule you wrote.
  Circular reasoning inflates all metrics.

  Root Cause 2 — SPATIAL AUTOCORRELATION
  ─────────────────────────────────────────
  Neighbouring grid cells (0.5° × 0.625° apart) share nearly
  identical climate patterns. Our split is temporal (train years
  vs test years), but the SAME 336 spatial locations appear in
  both sets. The model memorises local spatial patterns from the
  training period and applies them trivially to test-period data
  at the same locations.

  Root Cause 3 — CLASS IMBALANCE  (masking baseline)
  ─────────────────────────────────────────────────────
  {baseline_pct:.1f}% of samples are Low Risk.
  A "predict always-zero" classifier scores {baseline_pct:.1f}% accuracy.
  ANN's {ann_acc_pct:.2f}% only improves on this by {ann_acc_pct-baseline_pct:.2f} pp.
  F1 ({ann_m['f1']:.4f}) and ROC-AUC ({ann_m['auc']:.4f}) are far more
  informative metrics given this imbalance.

  Root Cause 4 — ROLLING FEATURE BLEED
  ──────────────────────────────────────
  RAIN_3M and RAIN_6M accumulate rainfall across months that
  straddle the 2019/2020 split boundary. December 2019 training
  values partially determine January 2020 test features.
  The split is less temporally clean than it appears.

  RECOMMENDATIONS FOR THE PAPER
  ───────────────────────────────
  ✓  Lead with ROC-AUC ({ann_m['auc']:.4f}) and F1 ({ann_m['f1']:.4f}) — not accuracy
  ✓  State accuracy with the imbalance context (75% baseline)
  ✓  Acknowledge proxy-label limitation explicitly in Limitations
  ✓  Recommend future validation against EM-DAT / UNOSAT / NIMET
     historical Nigeria flood event records
  ✓  Recommend spatial k-fold cross-validation as future work
     (hold out entire geographic zones, not random rows)
""")
